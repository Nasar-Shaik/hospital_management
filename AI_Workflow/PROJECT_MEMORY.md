- **Access-token revocation fails OPEN when Redis is down** · `middleware/authenticate.ts` + `core/redis/redis.ts` · the blocklist is a cache, and hard-failing every authenticated request during a Redis outage would take the hospital down — a worse outcome than a ≤15-minute revocation delay · interest: a logged-out or compromised token stays usable until it expires (bounded by `ACCESS_TOKEN_TTL_SECONDS`), and ADR-0009 explicitly accepts that bound · payoff trigger: if a customer's threat model demands immediate revocation, shorten the access TTL (a config change) before considering a DB-backed check on the hot path.
- **Auth events are not yet published to the outbox** · `modules/auth/` · the outbox collection exists (migration 0002) but no event publisher does; adding one ad hoc from auth would set the pattern for every future module by accident · interest: no `auth.login_failed` / `auth.token_reuse_detected` stream for the SIEM yet, so reuse detection is visible in logs but not as an event · payoff trigger: build the outbox publisher deliberately with A5 (Audit) and backfill these events (they are listed in EVENT_CATALOG).

## 7. Lessons Learned

- (2026-07-12) Writing editions _after_ modules exposed missing modules (dialysis, physio, ED triage…). Lesson: **map packaging → capabilities early**; the sales lens finds architecture gaps that the engineering lens misses.
- (2026-07-12) A mid-review architecture pivot (shared-collections → DB-per-tenant) touched 7 documents. Lesson: keep tenancy assumptions centralized (Doc 03 §1 + ADR) and referenced, not restated, elsewhere — restatements are what go stale.
- (2026-07-12) ADR-0003 (Vite SPA) was correct for its stated scope and superseded within a day when the scope statement changed (public/SEO/white-label surfaces became first-class). Lesson: **an ADR is only as durable as its Context section** — write the scope assumptions explicitly so it's obvious when they break; the supersession process worked exactly as designed.
- (2026-07-12, Phase 1B) The module boundary rule _forced_ a better design. Putting `users`, `credentials` and `roles` in one "auth" module was the obvious move, and it would have created an import cycle (auth needs roles for the token; rbac needs users for bindings). Splitting identity into `users` ← `auth` / `rbac` removed the cycle **and** produced a module where every secret in the platform lives in exactly one folder. Lesson: **when a boundary rule is inconvenient, the design is usually wrong, not the rule.**
- (2026-07-12, Phase 1B) The auth suite passed on its first run — which was itself suspicious. Deliberately breaking the tenant-claim check (`if (false && …)`) proved the isolation test failed as intended; without that step, a vacuous pass and a real pass are indistinguishable. Lesson: **for the assertions that matter most, verify the test fails when the property is removed.** A green suite only means something if you know it can go red.

## 8. Common Mistakes to Avoid (grows with experience)

- Using `suppliers`/`equipment` as collection names (rulings N1/N2 — they're aliases/views of `vendors`/`assets`).
- Putting business logic, DB access, or business API routes inside Next.js (`app/api/*`) — Next.js is presentation-only; Express is the only API (ADR-0012, ruling N9).
- Scaffolding new frontend features with Vite — Vite survives only as Vitest + `packages/ui` playground tooling.
- Putting per-hospital data in the master DB or vice versa — check Doc 03 §2 placement table every time.
- **Granting a commercial permission to a hospital role.** `plan:manage` / `featureflag:manage` decide what a customer PAYS FOR. They belong to the SUPERADMIN group and must never be inherited by TENANT_ADMIN — a customer who can toggle their own flags has a free upgrade. (Happened once; see §1.)
- **Browsing a tenant on the real domain in local dev.** `*.paperlesstech.in` has **wildcard DNS pointing at the production server** — `demo.paperlesstech.in:3000` in a browser goes to production, not your laptop. Use `<slug>.localhost` locally (`TENANT_BASE_DOMAIN=localhost`); it resolves to 127.0.0.1 with no hosts-file entry.
- **Hardcoding an API base URL in the frontend.** `http://localhost:4000` resolves to NO hospital: the browser cannot set `Host`, so the hostname it is browsing is the only thing that selects a tenant database. Configure a PORT (`NEXT_PUBLIC_API_PORT`) and derive the origin from `window.location.hostname`.
- **Shipping a migration without running the fleet job.** A tenant provisioned before the migration keeps running the old schema forever and fails in ways that look like bugs (an admin with zero permissions). Run `pnpm --filter @medicore/api migrate -- --all` after any release that adds a migration or changes the permission catalog.
- **Assuming a loopback address means a local database.** (2026-07-13 near-miss.) An SSH tunnel — `ssh -L 27018:127.0.0.1:27017 user@remote` — bound the _same_ loopback port as our dev Mongo and silently won the bind over Docker. Every connection to `127.0.0.1:27018` then reached a **remote** server, and our integration tests call `dropDatabase()`. Nothing was lost, but only by luck. The harness now refuses to run unless the host is loopback **and** the server has no auth (our dev container runs open; real servers do not), and it will only drop databases named `test_*` / `hms_test-*`. If a suite suddenly refuses to run, check `lsof -nP -iTCP:27018 -sTCP:LISTEN` and `docker ps` — something else has the port.
- **Omitting `directConnection=true` from a Mongo URI in dev.** The dev replica set advertises its member as `localhost:27017`, so the driver's topology discovery redirects a host-side connection to whatever else listens on port 27017 (on this machine: an unrelated `school_mongodb`). Symptom: `getaddrinfo ENOTFOUND mongodb`. Transactions still work with a direct connection to the RS primary.
- **Stamping fields in Mongoose `pre("save")`.** Schema validation runs _before_ save hooks, so a `required` field stamped there fails validation. Stamp in `pre("validate")` (this is why `tenantScopePlugin` does).
- **Writing an integration test that touches Mongo but not Redis.** The tenant registry is a **read-through cache**: dropping the master DB while `tenant:{slug}` is still cached leaves the app resolving a tenant that no longer exists (symptom: "Slug already taken" on a freshly dropped database). Test setup must drop **both** — `dropDatabases()` **and** `flushTestCache()`. The application never produces that split-brain state on its own; only a test harness can.
- **Asserting on a fail-soft dependency without running it.** Cache helpers fail soft by design, so an auth test that checks "the logged-out token is blocklisted" **passes vacuously with no Redis running** — "revoked" and "never revoked" look identical. This is why the auth suite asserts Redis is reachable and CI runs a real `redis` service. Any future assertion that rests on a fail-soft path needs the same treatment.
- **Importing an ambient `const enum` from a library under `isolatedModules`** (e.g. `Algorithm.Argon2id` from `@node-rs/argon2`) — it typechecks in an editor and fails the build. Pin the value and assert the result instead (`core/crypto/password.ts`).
- **Forgetting `asyncHandler` on an async Express route.** Express 4 does not forward rejections from async handlers: the error never reaches the error middleware and the client hangs until timeout. Every async route wraps in `asyncHandler` (`core/http/asyncHandler.ts`).
- Aggregating dashboards from OLTP collections "temporarily."
- Confusing the hospital's own helpdesk (`helpdeskTickets`, tenant DB) with SaaS support (`supportTickets`, master DB).
- Treating `00-PROGRESS-TRACKER.md`/this file as optional paperwork — they are the only memory the next agent has.
